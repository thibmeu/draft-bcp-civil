   Problem: CDNs sit between clients and origins Goal: Responsible
   traffic management without breaking the open web

2.  Conventions and Definitions

   The key words "MUST", "MUST NOT", "REQUIRED", "SHALL", "SHALL NOT",
   "SHOULD", "SHOULD NOT", "RECOMMENDED", "NOT RECOMMENDED", "MAY", and
   "OPTIONAL" in this document are to be interpreted as described in
   BCP 14 [RFC2119] [RFC8174] when, and only when, they appear in all
   capitals, as shown here.

   The following terms are used throughout this document:

   Active signal:  Cryptographically verifiable client property

   Passive signal:  Inferred/heuristic client property

   Graduated response:  Configurable action spectrum

3.  Recommended best practices

   The following best practices should be followed and are already
   applied by a vast majority of large-scale reverse proxy on the
   Internet:

   *  list the subsection for easy consumption

3.1.  Protocol neutrality

   CDN traffic management systems MUST support open, standardized
   protocols for client identification and access control.
   Implementations SHOULD avoid default configurations that rely on
   proprietary mechanisms or hardcoded allowlists.

3.2.  Graduated enforcement

   Operators SHOULD support configurable response tiers beyond block/
   allow (e.g., rate-limit, challenge, degrade).

   Example: Suspected automation → reduce rate limit; confirmed abuse →
   block.

3.3.  Active signals over passive fingerprints

   Implementations SHOULD prefer cryptographically verifiable client
   credentials (e.g., HTTP Message Signatures, Privacy Pass tokens) over
   passive fingerprinting techniques (e.g., TLS characteristics, IP
   heuristics).

3.4.  Behaviour-based classification

   Operators MUST classify traffic by defined behaviors (e.g.,
   "excessive request rate") rather than client type (e.g., "bot").

   Example: "Request rate >100/min from single IP" not "bot detected".

3.5.  Implementation consistency

   Cloudflare products should natively support and simplify adherence to
   the open web and bot standards that Cloudflare publishes and promotes
   externally.  This is true of "CDN" products, but also of workers or
   zero trust.

   Example: Cloudflare offers origins to serve content-signal allowing
   creators to specify preferences.  We should make it easy to consume
   in Workers.  Similarly, as Cloudflare CDN identify platforms, we
   should ensure that Workers and ZT identify themselves as well.
